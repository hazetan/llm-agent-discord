# Discord_Bot


## 1. プロジェクト概要
- LLM APIを通したローカルエージェントAIをDiscord Botとして動作させる．
- セッション単位で隔離されたDockerサンドボックス環境内で，コード生成・コマンド実行・自己修正・Git管理を自律的に遂行する．


## 2. 主な機能
※ コマンドに`<>`記号を書く必要はありません．
- `./start <目標>` : 新規セッションを発行し，エージェントの自律タスクをバックグラウンドで開始する．
- `./stop [session_id]` : 指定した実行中または待機中のエージェントタスクを中断する．
- `./queue` : 非同期タスクキューの稼働状況および待機セッション一覧を確認する．
- `./tell <メッセージ>` : 質問待機中（`ask_human`）のエージェントに対して回答を送信する．
- `./inject <メッセージ>` : 実行中のエージェントに対して，人間の判断や追加の指示を次ステップへ割り込みで提供する．
- `./project_status` : 最新セッションのステータス，目標，直近のアクティビティ履歴を確認する．
- `@Botメンション <質問>` : エージェントループを介さず，LLMと単発の質疑応答を行う．


## 3. 使用技術
- **言語** : Python
- **フレームワーク・ライブラリ** : discord.py, SQLAlchemy, aiohttp, python-dotenv, ddgs, Docker SDK for Python
- **インフラ・環境** : Docker（実行環境のサンドボックス化）, SQLite（セッション・ログ・ナレッジの永続化 / WALモード）, Git（自動チェックポイント・ロールバック管理）
- **LLMバックエンド** : llama-server（OpenAI互換推論・Embeddingエンドポイント）, GGUF形式ローカルModel
- **外部API** : DuckDuckGo API（Web検索・スクレイピング）


## 4. セットアップ手順
- Dockerをインストールし，実行ユーザーをdockerグループへ追加
`curl -fsSL https://get.docker.com | sh`
`sudo usermod -aG docker $USER`

- サンドボックス用コンテナイメージをプル
`docker pull python:3.12-slim`

- Python仮想環境を構築
`python3 -m venv .venv`
`source .venv/bin/activate`

- 主要ライブラリをインストール
`pip install -r requirements.txt`

- 環境変数ファイル（`.env`）を作成し，各種パラメータを設定
`DISCORD_TOKEN` / `LLAMA_SERVER_URL` 等を記述

- 実行スクリプトに権限を付与
`chmod u+x run`

- コマンド実行（tmux推奨）
`./run`


## 5. アップデート履歴
- `aiohttp`を用いた`llama-server`との非同期通信およびメンション応答・長文分割送信機能の実装
- SQLite（WALモード）とSQLAlchemyを用いたセッション（`GoalSession`）・作業履歴（`Activity`）・計画管理（`Planner`）の永続化．
- Function Callingによるファイル生成・コマンド実行ツールと，ディレクトリトラバーサル防止ガードの実装．
- 動的コンテキスト圧縮機構および`Planner`テーブルを用いた長期タスクの文脈引き継ぎ機能の実装．
- チャンネルID・メッセージIDの記録による，Bot再起動時の未完了セッション自動再開（リカバリ）機能の実装．
- `.env`による設定値の一元管理，ツール引数のパス正規化，およびLLM推論エラー時の自動リトライ処理の追加．
- セッション別ワークスペースの完全分離と，タスク完了時の成果物自動ZIPアーカイブ出力機能の実装．
- 単一Embedメッセージのリアルタイム編集による進捗ダッシュボードと，操作用UIボタン（中断・ファイル一覧・ZIP出力）の実装．
- Dockerコンテナによるコマンド実行環境の完全サンドボックス化，およびGit自動コミット・ロールバック機能の導入．
- DuckDuckGo（`ddgs`）を用いたWeb検索・URLテキスト抽出ツール，および人間への質問（`ask_human`）・割り込み指示（`./inject`）機能の実装．
- 大規模ファイル生成時のトークン切断を防ぐ差分置換（`replace_in_file`）およびマーカー挿入（`insert_into_file`）ツールの追加．
- 単一責任の原則に基づくモジュール分割リファクタリングの実施．
- Docker SDK for Pythonの導入によるコンテナ管理の抽象化とマルチホスト分散実行対応．
- 非同期タスクキューの導入による同時実行ワーカー数の制御と待機ステータスの可視化（`./queue`）．
- ベクターストア（RAGアーキテクチャ）の統合によるトラブルシューティング知見の動的抽出とプロンプト自動注入．
- コンテキストサイズに応じたトークン上限の動的スケーリング，カテゴリ別トークン消費モニタリング，およびセッション別詳細ログ（`.log/session{id}`）出力機能の実装．
